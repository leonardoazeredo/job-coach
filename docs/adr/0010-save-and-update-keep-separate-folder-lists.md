# Save and Coach update each keep their own folder list

Two lists in the engine look like one fact written twice, and are not. `USER_DATA_FOLDERS` in `lib/save.ts` is what a Save commits: the four User data folders, whole. `isEngineFile` in `lib/update.ts` is what a Coach update may replace: everything except the user's own paths, the Local work files, installed packages and git's folder. They stay separate, each beside the operation it serves, each with a comment that names the other and says why they differ. We keep them apart because they answer different questions, and the answers cross: `pipeline/README.md` and `pipeline/_templates/` are engine files that an update replaces and a Save also commits, with the rest of their folder, while `discovery/` and `.coach/` are neither saved nor replaced. So a path has two answers, not one kind, and any single source for both would hold both lists again behind a wider interface. The cost we accept is that a new top-level folder is placed twice, once for saving and once for updating, by someone who has read both comments. This applies ADR 0007: what is shipped and what is one person's stays decided in the engine, in the two places that act on it. Decided in #25 and kept when an architecture review proposed the shared module again.

## Considered options

- **One list, read by both**: rejected because the sets differ in both directions. Reading the saved folders as "never replace" would stop an update refreshing the README and templates inside `pipeline/` and `experience-bank/`; reading the update's list as "save everything else" would commit saved pulls and drafts.
- **One module that classifies a path as Engine, User data or Local work files, with both lists derived from it** (proposed by an architecture review): rejected because one kind per path cannot say that an engine file inside a saved folder is both replaced and saved. The module would need a second answer per path, which is the two lists with a seam nothing else varies across.
- **A test that the two lists agree**: rejected because they are not meant to. `isEngineFile` has its own test, on the paths that matter, in `update.test.ts`.
